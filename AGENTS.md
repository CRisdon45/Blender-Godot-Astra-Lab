# Blender-Godot Astra Lab agent instructions

Start with [CURRENT_AUTHORITY.md](CURRENT_AUTHORITY.md), then the task-relevant run or evidence instructions.

- This is an offline courtyard/3D rendering research lab. Godot is its final render target; Blender previews are intermediate evidence.
- Product authority stays in Design-Platform: native Android Plan + persistent embedded Godot Perspective + native integrated Estimator + renderer-neutral core. Do not start Godot 2D Plan work.
- Lab geometry inferred from a picture is not exact project geometry, quantity, botanical, or commercial truth. No runtime AI dependency belongs in the product.
- Use an identified visual target and named scenario. Compare actual Godot output against that target; do not treat the current output as an approved Northstar.
- Follow [the evidence protocol](docs/EVIDENCE_PROTOCOL.md). Separate supported capture behavior from proposed automation; record unavailable references and measurements honestly.
- Preserve manual edits before running regenerators, which replace Blender, GLB, and editable Godot files. Keep experiments and generated evidence bounded to the authorized task.
- Perform authorized reversible work directly. Ask only for a still-unresolved consequential decision; prepare the concrete evidence first.
- Docs-only work requires link and diff checks. Rendering changes require import, graphics-backed scene execution, log review, and visual inspection; headless import alone is not visual proof.
- Promote only reviewed, versioned reusable files with Design-Platform integration and target-device evidence. A successful desktop capture does not establish Android Mobile/Vulkan parity.
